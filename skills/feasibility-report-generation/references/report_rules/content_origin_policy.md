# 内容来源与复用策略

## 为什么要分来源

可研报告中“可以跨项目复用”的内容和“必须项目逐案确定”的内容完全不同。通用 Skill 的关键不是多写模板，而是防止历史案例事实污染新项目。

| 类型 | 是否可跨项目自动复用 | 典型内容 | 正式出具前要求 |
|---|---|---|---|
| PROJECT_FACT | 否 | 企业、厂址、产能、流量、设备、价格、投资 | U/PA/EA/FA/C 证据 |
| NORMATIVE_REUSABLE | 是（候选） | 法律、国标、行标、编制办法 | 校核现行有效版本 |
| CONDITIONAL_TEMPLATE | 条件成立才可 | “沿用现有路线”“依托现有系统” | 必须有事实/C支持条件 |
| CASE_REFERENCE | 只做参考 | 历史可研的章结构、表式、表达方式 | 禁止转成新项目事实 |
| LLM_NARRATIVE | 可生成 | 连接句、解释、摘要 | 只能消费有证据内容 |

## 最容易出错的四件事

1. 从历史案例复制“全部依托现有公用工程”，但新项目没有做系统余量校核；
2. 从案例复制企业名称、地点、装置规模或设备数量；
3. 把旧版标准编号当作当前有效版本直接正式出具；
4. 把“算法没有给”改写成一个听起来合理的工程数字。

以上四种行为在 Writer Gate 中均应阻断。
