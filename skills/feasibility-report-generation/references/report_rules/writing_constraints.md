# 写作约束

生成报告叙述、确定性正文或审查章节草稿时，使用本文件作为详细写作约束的单一事实源。

## 事实来源边界

- 报告正文只使用 `engineering_facts` 产出的 Engineering Facts、`work_package` 指定的章节事实/研究任务、Agent 已校验研究结果、确定性计算结果和用户确认输入。
- 章节写作阶段不得读取原始算法文件，不得绕过 `engineering_facts`、`work_package` 与 `report_finalize` 边界直接采用算法中间结果。
- 未经用户确认或 Tool 确认的工程事实不得写成确定结论。
- 不写入未经确认的工程数字；缺失工程条件保持缺口，不用公开资料或历史案例替代企业实际数据。
- `candidate recommendation` 不等于 `adopted scheme`；正文只使用最终确认方案。

## 结构与章节适用性

- 不改变固定章节结构、章节编号或 Tool 生成的允许标题。
- 按 Chapter Plan 判断章节适用性；`disabled` / `not-applicable` 章节不得生成正文、Research 任务或 LLM 草稿。
- 章节内容只覆盖该章节允许表达的事项，不把其他章节结论提前挪入。

## 内部词屏蔽

- 报告正文不得暴露 Evidence ID、URL、JSON、Skill、Provider、PA、EA、FA、内部拓扑、worker、cache、artifact、schema、Tool 调用细节或其他实现词。
- 不描述候选得分、验证优先级、算法排序、上下游内部依赖或系统运行过程。
- 外部资料只能转写为业务可读结论，不在正文呈现检索、缓存、证据编号或机器处理痕迹。

## 缺失数据与经济指标

- 缺投资、财务、价格、收益、成本、税费、折现率、回收期、IRR、NPV 等输入时，不生成推测金额或评价指标。
- 经济评价缺口只能写成待补充条件、测算边界或暂不形成定量评价，不得用行业均值补齐企业项目数据。
- 年化、能耗折标、财务缺口等口径以 Tool/内部规则产物为准；宿主 Agent 不自行按 reference 重新计算。

## 重点章节约束

- 1.2 是决策摘要，写项目是否具备继续推进条件、关键依据和保留缺口。
- 第 26 章是全报告的最终综合判断，承接全报告章节结论。
- 避免 1.2 与第 26 章大段重复：1.2 偏决策摘要，第 26 章偏综合结论和后续建议。
- 4.1.3 只写工程方案比较和推荐理由，不写候选得分、验证优先级、算法排序或内部拓扑推理。
- 4.2.1 按物料流和工艺段描述流程，不机械串联设备节点。
- 4.2.4 按 Tool/内部实现应用的设备规则表达新增、改造、利旧、无变化分类，不自行重判设备状态。
- 10.5 按 Tool/内部实现产出的能耗结果表达，不自行补算综合能耗或折标煤。

## 生产安全

- 生产模式交付物拒绝测试 Evidence、测试正文、测试标记和示例占位内容。
- 不把 `test_only`、mock、sample、fixture、demo-only 等内容写入正式报告。
- 发现草稿或证据含测试来源时，停止将其并入正文，回到对应 Tool 状态修正产物。
