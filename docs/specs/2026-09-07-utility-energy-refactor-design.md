# 公用工程汇总与能耗折算重构设计

## 目标

工程事实整理 Tool 在一次执行中，从设备专业结果中识别并汇总公用工程，按年运行时间形成可复算的全年消耗量，并使用 `src/engineering_facts/rules/energy_conversion_rules.json` 完成可计算项的确定性折算。报告生成 Tool 只消费整理结果动态制表，不再硬编码能源介质。

## 边界

- 保持工程事实 JSON 的 11 个顶层根、Schema 版本和两个 Tool 的外部调用方式不变。
- 公用工程来源限定在工程事实中的设备专业数据，不从工艺物料流股的普通 `medium` 字段误识别。
- 同一介质按设计/改造工况分别整理；只有单位和年运行时间足以确定年量时才计算全年消耗量。
- 规则库有匹配系数且必要输入完整时直接折算。
- 缺系数、单位不匹配、缺蒸汽压力/等级或只有热负荷而无实物量时，保留条目和明确原因，不猜测、不丢弃。
- 不修改 MCP Server、根 Skill、UI、既有顶层 Schema 和报告章节结构。

## 数据流

1. `src/engineering_facts` 继续整理设备事实。
2. 在 `derived_facts.utility_consumption_summary` 中输出规范化后的公用工程条目、来源对象、工况、输入量和可复算年量。
3. 在 `derived_facts.energy_conversion` 中输出核算体系、逐项折算结果、未折算原因和合计值。
4. `src/report_generation` 的 `utilities` builder 优先读取公用工程汇总。
5. `energy` builder 只读取折算结果和未折算项，动态生成表头及表行；没有识别结果时只输出统一的缺口行，不再固定生成电力、蒸汽、导热油和循环水。

## 规则

- 默认采用 `standard_coal`；不混用标准煤和标准油体系。
- 设备中识别到的公用工程默认进入本次能耗整理。
- 规则库覆盖的介质直接折算；规则库未覆盖的介质标记为缺失系数。
- 标准油蒸汽按实际表压或可信压力等级匹配；输入不足时阻塞该项。
- 每个计算结果保留规则编号、系数、系数单位、标准、条款和规则版本。

## 验证

- 工程事实 Tool：识别、归一化、去重、年化、标准煤折算、标准油蒸汽、缺系数、缺数量、单位不匹配测试。
- 报告 Tool：动态公用工程行、动态能耗行、合计、未折算原因、无数据缺口行，以及不再出现固定四行的回归测试。
- 运行两个重构 Tool 的全部单元测试、compileall 和 Schema 校验。
